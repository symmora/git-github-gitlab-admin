# Defect Registry

Реестр дефектов, найденных при тестировании и реальном использовании скилла.

GitHub Issues используются как оперативная система учёта. Этот файл фиксирует правила и сводное состояние качества.

## Что регистрировать

- ошибочное или неоднозначное поведение скилла;
- неверные команды, пути, зависимости или инструкции;
- portability-проблемы;
- пробелы в тестах;
- regression;
- safety-проблемы;
- неудобства, из-за которых агент с высокой вероятностью выбирает неправильный путь.

## Карточка дефекта

Для каждого дефекта желательно фиксировать:

- источник/сценарий обнаружения;
- компонент и файл;
- ожидаемое поведение;
- фактическое поведение;
- severity;
- шаги воспроизведения;
- исправление;
- regression test или причину, почему автоматический тест неприменим;
- связанный Issue/PR/commit.

## Рекомендуемые labels

`skill-bug`, `docs`, `portability`, `dependency`, `test-gap`, `regression`, `safety`, `agent-ux`.

## Жизненный цикл

`discovered → reproduced → fixed → regression-covered → verified`

Закрытие Issue означает, что исправление проверено. Если проблема воспроизводится снова, Issue переоткрывается либо создаётся regression Issue со ссылкой на исходный дефект.
