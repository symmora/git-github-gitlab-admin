# Skill Qualification

Этот раздел описывает воспроизводимую квалификацию `git-github-gitlab` в реальных и тестовых сценариях.

## Цель

Оценка качества скилла должна подтверждаться не только статическим ревью, но и практическим использованием. Любой обнаруженный дефект становится входом в цикл улучшения: регистрация → исправление → regression test → повторная квалификация.

## Qualification pipeline

1. Structural validation — структура, frontmatter, ссылки и progressive disclosure.
2. Dependency validation — наличие и корректность `git`, `gh`, `glab`, а также опциональных инструментов.
3. Scenario tests — happy path и типовые рабочие сценарии.
4. Failure-path tests — ошибки авторизации, отсутствующие зависимости, неверное состояние репозитория и другие ожидаемые сбои.
5. Safety tests — destructive operations, подтверждения и защита общей истории.
6. Portability tests — чистое окружение и разные способы размещения/запуска скилла.
7. Regression tests — каждый исправленный воспроизводимый дефект по возможности получает тест.
8. Scoring — повторная оценка после изменений.

## Команды проверки

```bash
bash -n scripts/git-router.sh tests/test-router.sh tests/test-install.sh
bash tests/test-router.sh
SKILLS_CLI=/absolute/path/to/skills bash tests/test-install.sh
```

Последняя команда запускает четыре сценария: CLI и ручное копирование из
`skills/<name>/` и из самостоятельного git-репозитория. Без `SKILLS_CLI`
два CLI-сценария явно пропускаются и такой прогон не является полным.
Workflow `.github/workflows/quality.yml` устанавливает `skills@1.7.0`.

Статические тесты с локальными git-фикстурами не подтверждают доступ к
приватному GitHub, авторизацию `gh`/`glab` и работу этих платформ; это
отдельные квалификационные пункты.

## Правило качества

Текущий score — это состояние качества на момент последней квалификации, а не постоянная характеристика. Существенный дефект должен отражаться в defect registry и учитываться при следующей оценке.
