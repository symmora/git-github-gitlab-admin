# Regression Tests

Этот раздел фиксирует правило: каждый воспроизводимый дефект, который был исправлен в `git-github-gitlab`, по возможности должен получить regression test или явную проверку, не позволяющую той же ошибке вернуться незаметно.

## Что сюда попадает

- ошибки в `SKILL.md`, frontmatter и ссылках;
- поломки `scripts/git-router.sh`;
- ошибки в командах `git`, `gh`, `glab` и сценариях их использования;
- проблемы авторизации и отсутствующих зависимостей;
- различия поведения в clean environment;
- ошибки размещения skill из skills-repo и обычного git-repo;
- сценарии с `skills-cli` и без него;
- safety-регрессии вокруг destructive operations;
- portability-регрессии между окружениями.

## Формат записи

Для каждого regression case фиксируются:

- ID связанного дефекта или GitHub Issue;
- исходный сценарий воспроизведения;
- ожидаемый результат;
- автоматизированный тест или ручная проверка;
- путь к тесту/скрипту;
- версия или commit, где исправление появилось;
- статус последнего прогона.

## Минимальное правило

Исправление дефекта не считается полностью закрытым, если можно разумно автоматизировать проверку, но regression test не добавлен.

Если автоматизация невозможна или неоправданно сложна, это должно быть явно отмечено в defect registry вместе с ручной процедурой проверки.

## Связь с квалификацией

Regression tests входят в общий qualification pipeline. Перед повышением или подтверждением score необходимо проверить, что ранее закрытые существенные дефекты не воспроизводятся снова.
